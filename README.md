# MAV — My Awesome Virtual Intelligence Suite

A local, extensible personal assistant powered by **Gemini 2.5 Flash**. MAV takes natural language commands, decomposes them into executable pipelines, builds any missing tools on-the-fly using the LLM, and enforces security through the **ONI harness**.

---

## Architecture

```
User Input (text)
      │
      ▼
handle_slash_command()       ← intercepts /config, /trust, /allow, /block, etc.
      │  (if not a slash cmd)
      ▼
interpret_command()          ← Gemini: decomposes input into a DAG pipeline JSON
      │
      ├─ missing tools? ──► ToolBuilder.build_tool()
      │                          ├─ Gemini generates Python tool file
      │                          ├─ AST scan (ONI: blocks subprocess, socket, os.system, …)
      │                          ├─ ToolTester runs auto-generated test
      │                          ├─ FAIL? → debug_tool() retry loop (max_retries from config)
      │                          └─ PASS → registered in commands_list.json
      │
      ▼
execute_pipeline()
      ├─ ONI pre-flight scan   ← blacklist → abort; greylist → batch user prompt
      │
      └─ call_command()        ← each tool runs in an isolated subprocess (run_tool.py)
            │
            └─ Final Result

Background (daemon threads)
──────────────────────────────
TaskRunner (whitelist_only trust)
  ├─ short_term_worker   — every 15 min: promote high-signal turns to ChromaDB
  └─ long_term_worker    — every 8 h:   archive aged short-term → long-term memory
```

## Features

### Core
- **Natural language → DAG pipeline**: Gemini decomposes any command into an ordered list of function calls with `$node_id` dependency references.
- **Self-building toolset**: Missing tools are generated by Gemini, written to `tools/`, and validated before use — all within the session.
- **Test generation + LLM debug loop**: Every new tool gets an auto-generated test. Failures trigger LLM-assisted retries (configurable, default 3).

### ONI — Operating System & Network Interface
Security harness that gates all system, network, and filesystem I/O.

| Feature | Detail |
|---|---|
| **Trust levels** | `ask` (default), `yolo` (no checks), `whitelist_only` (deny-by-default) |
| **Pre-flight scan** | Entire pipeline checked before any node runs |
| **Blacklist** | Instant pipeline abort |
| **Greylist** | Single batch prompt to user before execution |
| **AST scanner** | Generated tools scanned for `subprocess`, `socket`, `os.system()`, etc. |
| **Subprocess sandbox** | Each tool runs in an isolated child process via `run_tool.py` |
| **Audit log** | Every ONI decision appended to `logs/oni_audit.jsonl` |
| **Background isolation** | Worker threads run at `whitelist_only` trust regardless of session trust |

### Three-Tier Memory
| Tier | Storage | Lifetime | Purpose |
|---|---|---|---|
| Working | In-process list | Session | Full recent context, token-capped |
| Short-term | ChromaDB + JSON | 7 days (configurable) | High-signal turns promoted by background worker |
| Long-term | ChromaDB + JSON | Permanent | Behaviours & facts promoted from short-term |

### Runtime Config (Slash Commands)
All settings changeable without restarting (except scheduler intervals):

```
/help                           List all commands
/config                         Print current config
/config set memory.top_k 10     Change any setting live
/config save / reload           Persist or discard changes
/config audit [N]               Tail the ONI audit log
/trust ask|yolo|whitelist       Change ONI trust level
/allow <cmd>                    Add to whitelist
/block <cmd>                    Add to blacklist
/greylist <cmd>                 Add to greylist
/unlist <cmd>                   Remove from all lists
```

### Built-in Tools
| Tool | Description |
|---|---|
| `get_current_datetime` | Returns current system date and time |
| `extract_date_from_datetime` | Extracts `YYYY-MM-DD` from a datetime string |
| `parse_natural_date_to_yyyymmdd` | Converts natural-language dates to `YYYY-MM-DD` |
| `search_news` | Searches NewsAPI for articles by query and optional date range |

## Setup

### Prerequisites
- Python 3.11+
- A Google Cloud / Gemini API key
- A [NewsAPI](https://newsapi.org/) key (for `search_news`)

### Install

```bash
cd ~/PerTools/MAV
python3 -m venv .
source bin/activate
pip install -r requirements.txt
```

> **Important:** Always run MAV from inside the venv (`source bin/activate`) to ensure the pinned ChromaDB version is used. Running with the system `python3` directly can cause ChromaDB schema errors.

### Configure `.env`

```
VERTEX_API_KEY="your-google-api-key"
NEWS_API_KEY="your-newsapi-key"
```

### Run

```bash
source bin/activate
python main.py
```

## Configuration

All settings live in **`data/mavis_config.json`** — a single file replacing all scattered constants. Edit it directly or use `/config set` at runtime.

```json
{
    "oni": {
        "trust_level": "ask",
        "whitelist": ["get_current_datetime", "search_news", ...],
        "greylist": ["restart_process", "pip", ...],
        "blacklist": [],
        "tool_execution_timeout_seconds": 30
    },
    "memory": {
        "max_token": 12000,
        "top_k": 5,
        "short_term_ttl_days": 7,
        "session_timeout_minutes": 30,
        "emotion_strength_threshold": 0.75
    },
    "toolbuilder": {
        "max_retries": 3,
        "forbidden_imports": ["subprocess", "socket", ...]
    },
    "scheduler": {
        "tick_seconds": 30,
        "short_term_worker_interval_minutes": 15,
        "long_term_worker_interval_minutes": 480
    }
}
```

> Scheduler interval changes require a restart. All other changes take effect immediately via `/config set`.

## Tool System

All tools live in `tools/` as individual Python files. Every tool:
- Has the **same name** as its file and its primary function.
- Returns `(0, result)` on success and `(-1, error_message)` on failure.
- Is registered in `data/commands_list.json` with its signature and description.

When MAV encounters an unknown command, `ToolBuilder` automatically:
1. Generates tool code via Gemini (with ONI security rules in the prompt).
2. Runs an AST scan — rejects tools that import `subprocess`, `socket`, etc.
3. Writes it to `tools/<name>.py` via ONI (approved path check).
4. Generates and runs a test.
5. If the test fails, retries with LLM debugging (up to `max_retries` times).
6. If all retries fail, leaves the file with a `# NEEDS MANUAL FIX` header.

### Adding a Tool Manually

Create `tools/my_tool.py`:
```python
from oni import call_network  # use ONI for all I/O

def my_tool(param: str) -> tuple[int, str]:
    status, result = call_network(f"https://api.example.com?q={param}")
    if status != 0:
        return -1, result
    return 0, result
```

Then add it to `data/commands_list.json`:
```json
{
  "my_tool(param: str) -> tuple[int, str]": "Description of what my_tool does."
}
```

And add the function name to `data/mavis_config.json` → `oni.whitelist`.

## Adding a Background Task

1. Create `tasks/my_task.py`:
```python
from core.helpers import log_it

def run():
    log_it("my_task ran.", "my_task")
```

2. Register it in `main.py` before `runner.start()`:
```python
import tasks.my_task as my_task
runner.register(
    my_task.run,
    interval_minutes=30,
    task_name="my_task",
    trust_level="whitelist_only",   # background tasks should always use whitelist_only
)
```

## Troubleshooting

### ChromaDB `KeyError: '_type'` on startup
The on-disk ChromaDB schema is incompatible with the installed version. Run:
```bash
./scripts/reset_chroma.sh
```
This wipes and recreates the empty collections. No conversation data is lost during the prototype phase.

### `ModuleNotFoundError` on startup
You're running with the system Python instead of the venv:
```bash
source bin/activate   # ← always do this first
python main.py
```
